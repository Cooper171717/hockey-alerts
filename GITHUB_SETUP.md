# Работа при выключенном ПК через GitHub

Этот вариант запускает одну проверку примерно каждые 10 минут на GitHub.
Сервер и включённый домашний ПК не нужны. Бесплатный вариант рассчитан на
PUBLIC-репозиторий и стандартный ubuntu-latest runner. Платные runner не включать.

1. Распакуйте НОВЫЙ архив в отдельную папку. В нём нет вашего токена.
2. На https://github.com/new создайте репозиторий `hockey-alerts`, выберите
   Public и включите Add README. Нажмите Create repository.
3. В репозитории выберите Add file → Upload files. Загрузите файлы из нового
   архива в корень, включая папку `.github`. Нажмите Commit changes.
   Не загружайте ZIP целиком, вашу старую папку, `.env` и `state.sqlite3`.
   Если `.github` не загрузилась, создайте файл вручную: Add file → Create new file,
   имя `.github/workflows/hattricks.yml`; вставьте содержимое одноимённого файла
   из архива и сохраните Commit changes.
4. Откройте Settings → Secrets and variables → Actions → New repository secret.
   Создайте два секрета (имена точно как ниже):
   - TELEGRAM_BOT_TOKEN — значение токена из вашего локального `.env`.
   - TELEGRAM_CHAT_ID — значение ID из вашего локального `.env`.
   Копируйте только значения, без названия переменной и знака `=`.
   В сам код токен и ID не вставлять. Секреты не показываются посетителям.
5. Settings → Actions → General → Workflow permissions:
   выберите Read and write permissions и Save. Это нужно для сохранения
   истории доставленных уведомлений. Workflow также явно запрашивает contents: write.
6. Остановите локального бота через Ctrl+C, чтобы два экземпляра не слали повторы.
7. Откройте Actions → Hockey alerts → Run workflow. Выберите основную ветку,
   оставьте Send a Telegram connection test включённым и нажмите Run workflow.
   Должно прийти тестовое сообщение. Затем выполняется проверка матчей.
8. Дождитесь зелёной отметки у запуска. Если она красная, откройте запуск
   и шаг с ошибкой. Теперь можно выключать компьютер.

При первом облачном запуске недавние хет-трики могут прийти повторно:
локальная история в облако не переносится. После этого workflow сохраняет
хеши отправленных уведомлений в cloud-state.json; этот файл не удаляйте.
В нём нет токена, открытого ID чата или текста сообщений. Хеширование не
следует считать шифрованием; файл служит только для устранения повторов.
История сохраняется коммитами только при появлении новых уведомлений.

GitHub может задержать или пропустить запуск при нагрузке. Если публичный
репозиторий неактивен 60 дней, расписание отключается. Его можно включить
снова на вкладке Actions; это особенно актуально в межсезонье.
Проверяйте Actions и письма GitHub об ошибках. Гарантии непрерывной доставки нет.

Ошибка одной лиги не мешает второй: доставленные сообщения сохраняются даже
при частичном сбое, а сам запуск отмечается как неуспешный. При отмене/аварийном
завершении либо ошибке сохранения истории возможны повторы. Не запускайте
другие workflow, записывающие cloud-state.json. При защите основной ветки,
запрещающей прямые коммиты, сохранение истории не сработает: используйте
отдельный личный репозиторий для этого бота.

После длительного сбоя сохраняется прежнее окно проверки: НХЛ — текущая и
предыдущая дата UTC, КХЛ — последние 36 часов. Это не архив всех хет-триков.

Остановить облачного бота: Actions → Hockey alerts → меню ⋯ → Disable workflow.
Для изменения токена измените соответствующий repository secret.
