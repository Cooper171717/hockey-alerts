# Уведомления о хет-триках КХЛ и НХЛ

Для бесплатного запуска при выключенном ПК см. [GITHUB_SETUP.md](GITHUB_SETUP.md).

Личный Telegram-бот на Python 3.11+. Дополнительные библиотеки не нужны.
Проверяет индивидуальную статистику матчей каждые 60 секунд. При трёх и более
голах отправляет имя игрока, команду, соперников, счёт, дату и ссылку на матч.
Голы в серии послематчевых буллитов не учитываются: используется статистика
голов игрока за матч. Четвёртая шайба повторного уведомления не вызывает.
Имена НХЛ приходят из источника преимущественно на английском.

## Подключение Telegram

1. Откройте https://t.me/BotFather в Telegram, отправьте `/newbot`, задайте имя
   и свободное имя пользователя, заканчивающееся на `bot`. Сохраните токен.
2. Скопируйте `.env.example` в `.env` в папке проекта. Вставьте токен после
   `TELEGRAM_BOT_TOKEN=`. Не публикуйте этот файл и не присылайте токен в чат.
3. Откройте созданного бота и отправьте ему `/start`.
4. В терминале в папке проекта выполните `python bot.py --chat-id`.
   Команда покажет ID личных чатов, написавших этому боту. Впишите свой ID
   после `TELEGRAM_CHAT_ID=` в `.env` (если ID несколько, выберите свой).
5. Выполните `python bot.py` и оставьте процесс работающим.

В Windows можно использовать `py` вместо `python`. Если Python не установлен,
установите Python 3.11 или новее с https://www.python.org/downloads/.
`/start` нужен Telegram для разрешения отправлять сообщения пользователю;
другие команды бот не обрабатывает. Получатель задаётся явно в `.env`.
Существующий webhook у того же бота несовместим с получением ID через getUpdates;
для этого проекта создайте отдельного бота.

## Пример уведомления

```text
🎩 Хет-трик! НХЛ

Игрок: Alex Ovechkin
Команда: Washington Capitals
Матч: Washington Capitals — Pittsburgh Penguins
Счёт на момент проверки: 4:2
Дата матча: 2026-10-17
Голы: 3

ссылка на матч
```

Это пример формата, а не сообщение о реальном матче.

## Работа круглосуточно

Компьютер или сервер должен быть включён и подключён к интернету.
С установленным Docker Compose, после настройки `.env`:

```sh
docker compose up -d --build
docker compose logs -f
```

Контейнер автоматически перезапускается; база уведомлений сохраняется в `data/`.
Остановить: `docker compose down`. При обычном запуске база `state.sqlite3`
находится рядом с `bot.py`. Сохраняйте её между перезапусками и запускайте
только один экземпляр бота с этой базой.

## Проверка

```sh
python -m unittest -v
python bot.py --dry-run
```

Первая команда запускает автономные тесты. Вторая обращается к реальным API,
печатает найденные хет-трики, ничего не отправляет в Telegram и не помечает
уведомления отправленными. Отсутствие вывода возможно, если хет-триков нет;
ошибки источников выводятся в журнал. `--once` выполняет один проход с отправкой.

## Особенности и ограничения

- Первый запуск также сообщит о найденных хет-триках в недавних матчах:
  НХЛ — текущая и предыдущая дата UTC, КХЛ — последние 36 часов.
  После длительного простоя матчи вне этого окна не восстанавливаются.
- Задержка составляет интервал проверки плюс время публикации статистики
  источником и сетевых запросов; точная доставка за минуту не гарантируется.
- Используются публичные API сайтов лиг, без гарантии стабильности формата:
  https://api-web.nhle.com/v1/score/now и
  https://khl.api.webcaster.pro/api/khl_mobile/events_v2.json.
  Ошибка одной лиги или матча не останавливает проверку остальных.
- При ошибке отправки уведомление будет повторно проверено. Если Telegram
  принял сообщение, но ответ потерялся, либо процесс завершился до записи
  в SQLite, возможен повтор. При обычном перезапуске повторы исключаются базой.
- Статистика может быть исправлена лигой после отправки. Бот не отзывает
  уже отправленные сообщения и не отправляет исправления.
- Токен, `.env` и базу не следует публиковать. Бот пишет в журнал только
  тип ошибки, чтобы секретный URL Telegram не попал в логи.

Код подготовлен для запуска. Создание учётной записи бота через BotFather,
настройка секретного токена и размещение на постоянно работающем сервере
выполняются отдельно; без них уведомления не отправляются.
